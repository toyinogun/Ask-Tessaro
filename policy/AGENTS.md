# policy

## Overview

The OPA tool policy, Layer 1 of Tessaro's authorization: may this caller's roles use this tool at all. OpenFGA (`authz/`) is Layer 2, record access; both must allow. Governing spec: [docs/specs/0005-tool-policy/index.md](../docs/specs/0005-tool-policy/index.md).

## Layout

- `gateway.rego`: package `tessaro.gateway`, rules `decision` (`allow` plus sorted `reasons`) and `allowed_tools`, both on one `deny_reasons` helper
- `gateway_test.rego`: package `tessaro.gateway_test`, the PRD 8.2 role by scope grid on fixture tools, plus deny reason, invalid input and listing tests, grouped by the AC they cover
- `tools.json`: generated by `tessaro_contracts.export`, lands at `data.tools`
- `role_scopes.json`: generated by `tessaro_auth.policy_export` from `ROLE_SCOPES`, lands at `data.role_scopes`

## Commands

```bash
just policy      # opa fmt --fail, opa check --strict, opa test --threshold 100, then just authz-test
just contracts   # regenerate tools.json and role_scopes.json; never hand edit them
curl -s -X POST localhost:8181/v1/data/tessaro/gateway/decision -d '{"input": {"kind": "human", "roles": ["employee"], "tool": "get_my_leave"}}'   # needs `just up`
```

## Conventions

- The folder stays flat: OPA loads a JSON file at its folder path, so `policy/data/x.json` would land at `data.data.x`.
- Input is only `{kind, roles, tool}` from a principal `tessaro-auth` already verified; never add an email, employee ID, workflow ID or token.
- Reasons are a fixed set: `invalid_input`, `unknown_tool`, `scope_not_granted`, `write_needs_worker`, `kind_role_mismatch`. The spec's truth table is normative.
- Both rules keep their `default`, so an empty OPA result always means OPA failed. Anything malformed, including a tool with no string scope, must deny.
- A write scope is one ending in `:write`, the same rule as `Scope.is_write`; no human input is ever allowed one, whatever the data says.
- Rego v1 syntax (no `import rego.v1`). `opa check --strict` rejects unused arguments and variables, so name them `_`. A new rule needs a test, or the 100% coverage gate fails.
- Ship only `gateway.rego` and the two JSON files to the cluster ConfigMap, never `*_test.rego`.
- Root `AGENTS.md` rules apply.
